Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI backend that serves in-memory data loaded from JSON files. There is no database.

Overview

A demo application for a Claude Code workshop. It covers inventory tracking, order management, demand forecasting, backlog monitoring, spending analytics and quarterly reports for a fictional factory with warehouses in San Francisco, London and Tokyo.

System architecture

The browser loads the SPA from Vite. All data comes from the FastAPI server over HTTP. The server reads the JSON files once at import time and keeps them as Python lists for the lifetime of the process.

Data flow

Every screen follows the same loop: a shared filter changes, the view refetches, the server filters in memory, the view derives what it displays.

  1. A filter changesFilterBar writes to module-level refs in useFilters (period, location, category, status). Because the state lives outside the function, every view shares the same instance.
  2. The view reactsEach view runs watch() on the filters it cares about. Dashboard and Orders watch all four, Inventory, Backlog and Demand watch location and category, Spending watches only the period.
  3. The request is builtgetCurrentFilters() returns an object, and api.js drops every value equal to all before building the query string for the Axios GET call to http://localhost:8001/api/....
  4. The server filters in memoryThe route calls apply_filters() for warehouse, category and status (exact or case-insensitive match), then filter_by_month(), which matches the month or quarter as a substring of order_date. Quarters expand through QUARTER_MAP.
  5. The response is validatedMost list routes declare a Pydantic response_model, so the JSON shape is enforced. Dashboard, spending and report routes return plain dicts and lists.
  6. The view derives what it showsRaw responses are stored in refs such as allOrders and inventoryItems. Totals, groupings and chart geometry are computed properties. Translation and currency conversion (fixed 1 USD = 150 JPY) happen at render time in the client.

Observations

Things worth knowing before changing the code, found while reading it.

Frontend calls routes the backend does not have. api.js defines tasks (GET/POST/PATCH/DELETE /api/tasks) and purchase orders (POST /api/purchase-orders, GET /api/purchase-orders/{id}). None of these exist in main.py. App.vue catches the error and logs it, so the task list falls back to the mock tasks from useAuth. Pydantic models for purchase orders are defined, and purchase_orders.json is an empty list.
Backlog.vue is not wired up. The file exists in client/src/views/ but is not imported in main.js, so no route reaches it. Backlog data is shown through the Dashboard instead.
Hard-coded API address. The base URL http://localhost:8001/api is written into api.js and again in Reports.vue, which bypasses api.js. CORS on the server allows every origin.
Duplicated quarter logic. QUARTER_MAP and filter_by_month() handle quarters for filtering, while get_quarterly_reports() repeats the month-to-quarter mapping with its own if chain.
State is read-only and ephemeral. Nothing writes back to the JSON files, so every restart returns the same data.
